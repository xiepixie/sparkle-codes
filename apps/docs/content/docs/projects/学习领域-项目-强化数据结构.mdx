# 数据结构【应用题】核心知识

#### 1. 核心定义与前提 (Core Definitions & Premises)

*   **408考试结构**:
    *   **总分与时间**: 满分150分，考试时间3小时。
    *   **形式**: 闭卷、笔试。
    *   **科目分值**: 数据结构 (45分)，计算机组成原理 (45分)，操作系统 (35分)，计算机网络 (25分)。该分值分布自2009年以来保持不变。
    *   **题型**: 单项选择题 (40题，每题2分，共80分) 和综合应用题 (大题，共70分)。
*   **数据结构科目结构**:
    *   **选择题**: 11道题 (第1-11题)，共22分。
    *   **大题**: 2道题，共23分。
*   **数据结构大题分类**:
    *   **算法题**: 要求编写代码，通常是实现一个完整的算法。
    *   **应用题**: 通常不要求或只要求编写少量代码（如数据结构定义），侧重于考察逻辑、过程分析、画图和简答。
*   **考研大纲 (Syllabus)**:
    *   **语言要求**: 算法实现只能使用 C 或 C++ 语言。
    *   **核心考察点**: 逻辑结构、存储结构、基本操作的实现，以及算法的时间和空间复杂度分析。
*   **大纲新增/变动考点**:
    *   **并查集及其应用**: 2022年新增，截至目前尚未考察。
    *   **堆及其应用**: 2024年“伪新增”，因2022年一道相关题目得分率低而加入大纲以示强调。
    *   **红黑树**: 2022年新增，截至目前尚未考察，预计更可能在选择题中出现。
    *   **字符串的模式匹配 (KMP)**: 在王道教材中是独立章节，但在大纲中仅为“查找”下的二级标题，提示其重要性可能被高估。
*   **前缀特性编码 (Prefix Code)**: 如果一个字符的编码不是任何其他字符编码的前缀，则这种编码具有前缀特性（例如哈夫曼编码）。
*   **正则k叉树 (Regular k-ary Tree)**: 一种非空k叉树，其中每个非叶子节点都恰好有k个孩子。

#### 2. 定理、原理与定律 (Theorems, Principles & Laws)

*   **备考核心原理：“输出倒逼输入”**: 在强化复习阶段，应将大部分时间（如80%）用于做题和主动练习（输出），以发现知识盲点，然后针对性地回顾课本和课程（输入），而不是反过来。
*   **算法题解题原则：“笨方法优先”**: 在考场时间有限的情况下，应优先采用最直接、最简单（哪怕效率不高）的方法快速解题，确保获得大部分分数，而不是花费过多时间追求最优解而导致无法完成。
*   **应用题命题原则**: 应用题倾向于考察那些代码实现复杂、冗长或难以在答题纸上完整呈现的算法和数据结构（如哈希表、复杂图算法、外部排序等），重点检验对算法执行过程和逻辑的理解。
*   **答题原则：“问什么答什么”**: 在回答综合应用题时，只回答题目明确提出的问题。除非题目要求“说明理由”或“给出过程”，否则不要画蛇添足，以免言多必失。

#### 3. 关键公式与方程 (Key Formulas & Equations)

*   **时间/空间复杂度表示法**: 普遍使用大O表示法分析算法效率，如 $O(1)$, $O(\log n)$, $O(n)$, $O(n \log n)$, $O(n^2)$。
*   **平均查找长度 (ASL - Average Search Length)**: 衡量查找算法效率的关键指标，需要针对成功和失败两种情况进行分析。
*   **散列表装填因子 (Load Factor)**: $\alpha = \frac{\text{表中元素个数}}{\text{散列表长度}}$，用于衡量散列表的饱和程度。
*   **正则k叉树性质**: 若有 $m$ 个非叶子节点，则叶子节点数量为 $(k-1)m + 1$。

#### 4. 逻辑推导与解题过程 (Logical Derivations & Problem-Solving Processes)

*   **算法题标准解题流程**:
    1.  **基本设计思想**: 使用中文清晰、分点描述算法的核心逻辑和步骤。
    2.  **代码实现**: 使用C/C++语言编写完整算法，关键之处需添加注释。
    3.  **复杂度分析**: 分析算法的时间复杂度和空间复杂度。
*   **应用题常见解题模式**:
    *   **画图**: 根据题意画出数据结构的初始、中间或最终状态示意图（如哈希表、树、图的邻接表）。
    *   **手算模拟**: 在草稿纸上模拟算法的每一步执行过程，推导出最终结果或过程中的关键状态。
    *   **简答**: 根据对数据结构和算法特性的理解，选择合适的方案或分析其性质。
*   **拓扑排序逻辑**:
    1.  找到图中所有入度为0的顶点。
    2.  选择一个入度为0的顶点，输出它。
    3.  从图中删除该顶点及其所有出边（即，将该顶点指向的其他顶点的入度减1）。
    4.  重复步骤1-3，直到所有顶点都被输出。如果在某一步找到的入度为0的顶点多于一个，则拓扑序列不唯一。
*   **普里姆 (Prim) 算法逻辑**:
    1.  从任意一个顶点开始，将其加入已访问集合U。
    2.  在所有连接U内顶点和U外顶点的边中，选择一条权值最小的边。
    3.  将这条边及其连接的U外顶点加入到最小生成树和集合U中。
    4.  重复步骤2-3，直到所有顶点都加入U。

#### 5. 应用技巧与注意事项 (Application Techniques & Critical Caveats)

*   **复习阶段转换**: 基础阶段侧重于“输入”（看书、听课），而强化阶段必须转向以“输出”（做题）为主，用做题来检验和巩固知识。
*   **大纲敏感性**: 必须关注每年9月份发布的新大纲，特别是新增考点，因为新增内容在未来几年考察的可能性很高。
*   **重视应用题中的复杂数据结构**: 对于树、森林、图、并查集等结构，其代码实现复杂，因此在应用题中，重点考察其逻辑结构定义（`struct`）、画图表示和过程模拟。
*   **算法性质分析的上下文**: 分析时间复杂度等性质时，必须紧密结合题目的具体要求。例如，在N个元素中找最小的10个，其复杂度是 $O(N)$ 级别，而不是对整个数组排序的 $O(N^2)$ 或 $O(N \log N)$。
*   **识别“应用”关键词**: 在大纲中，凡是提到“XX的应用”的章节，都是综合应用题的高频出题点。

#### 6. 核心思想、主题与题型 (Core Ideas, Themes & Problem Types)

*   **核心思想：“过程的艺术”**: 408数据结构考试的精髓在于深入理解算法执行的每一步动态过程，包括指针如何移动、数据如何变化等。
*   **核心主题一：算法题 (Algorithm Questions)**: 考察将算法逻辑转化为具体、正确、简洁代码的编程实现能力。
*   **核心主题二：应用题 (Application Questions)**: 考察对算法原理和数据结构的深度、概念性理解，强调分析、模拟和选择能力，而非直接编码。
*   **应用题七大题型原型**:
    1.  **画图呈现**: 描绘数据结构的状态。
    2.  **代码定义与基本操作**: 编写复杂结构的定义和核心基础函数。
    3.  **手算分析**: 模拟算法执行过程并得出结果。
    4.  **结构与算法选择**: 根据应用场景选择最优方案。
    5.  **算法性质分析**: 分析复杂度、稳定性、ASL等。
    6.  **文字描述思想**: 用自然语言阐述算法核心逻辑。
    7.  **性质推演**: 基于数据结构的数学特性进行推导，偏数学化。

## 1. 核心题型一：手算分析与画图呈现

### **目标与定义 (Objective & Definition):**
本模块旨在解决要求考生手动模拟算法执行过程、推演其结果，并以图形方式清晰展示数据结构在初始、中间或最终状态的问题。这是应用题中最核心、最基础的能力。

### **关键原理与公式 (Core Principles & Formulas):**
*   **核心原理：“过程的艺术”**: 深刻理解算法的每一步是对数据结构的具体操作，掌握状态的动态演变是解题的关键。
*   **关键概念**:
    *   **哈希表**: 冲突解决方法（如线性探测法）、装填因子计算。
    *   **树/图**: 邻接矩阵、邻接表的表示法，遍历过程（DFS/BFS），最小生成树（Prim/Kruskal）的构建步骤，拓扑排序的过程。
    *   **排序**: 外部排序中初始归并段的生成过程（如置换-选择排序）。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**
1.  **识别要素**: 快速确定题目考察的数据结构、待执行的算法以及输入数据序列。
2.  **建立初始状态**: 在草稿纸上清晰地画出数据结构的初始形态（如空的哈希表、图的邻接矩阵）。
3.  **逐步模拟**: 严格按照算法规则，处理输入序列中的每一个元素，并在图上更新数据结构的状态。例如，插入一个哈希表元素时，计算哈希地址，若冲突则计算下一个探测地址。
4.  **记录关键节点**: 在模拟过程中，标记题目要求的中间结果或最终状态。
5.  **清晰转绘**: 将草稿纸上最终确认的、或题目要求的特定状态图，工整地绘制在答题纸上。

### **典型实例与应用技巧 (Examples & Application Techniques):**
*   **实例1 (2024年真题)**: 考察哈希表。
    *   **任务**: 给定关键字序列、哈希函数和冲突解决方法，画出最终的哈希表，并计算查找特定关键字的对比序列。
    *   **技巧**: 准备一张表格，逐个处理关键字。第一列是关键字，第二列是初始哈希地址 $H(key)$，第三列是冲突后的探测序列，第四列是最终位置。这样可以保证过程清晰，不易出错。
*   **实例2 (2017年真题)**: 考察最小生成树 (Prim算法)。
    *   **任务**: 从指定顶点出发，使用Prim算法，依次写出被选中的边。
    *   **技巧**: 维护两个顶点集合：已加入MST的集合U和未加入的集合V。在草稿纸上，每次迭代时，清晰地列出所有连接U和V的边及其权值，从中选出最小的一条，然后更新集合U。

## 2. 核心题型二：结构与算法的选择及分析

### **目标与定义 (Objective & Definition):**
本模块旨在解决给出一个具体应用场景，要求考生基于对不同数据结构和算法特性的理解，选择最合适的方案，并对其性能（如时空复杂度、稳定性）进行分析。

### **关键原理与公式 (Core Principles & Formulas):**
*   **核心原理：权衡 (Trade-offs)**: 不存在万能的最优方案。选择必须基于具体需求，在时间效率、空间占用、操作便利性之间做权衡。
*   **关键公式/概念**:
    *   **复杂度**: $O(1), O(\log n), O(n), O(n \log n), O(n^2)$。
    *   **数据结构特性**:
        *   **顺序存储**: 随机访问快 ($O(1)$)，插入/删除慢 ($O(n)$)，空间连续。
        *   **链式存储**: 插入/删除快 ($O(1)$)，随机访问慢 ($O(n)$)，空间可动态扩展。
    *   **排序算法稳定性**: 相同关键字的元素，在排序后相对次序是否保持不变。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**
1.  **解析需求**: 明确场景的核心操作是什么（如频繁查找？频繁增删？）、数据规模多大、有无特殊限制（如内存限制）。
2.  **列出备选**: 针对需求，列出1-3个候选的数据结构或算法。
3.  **比较优劣**: 从时间复杂度、空间复杂度、实现难度等方面，对比分析各备选方案的优缺点。
4.  **做出决策并论证**: 选择最符合需求的方案，并用1-2句话简明扼要地阐述选择理由。
5.  **进行分析**: 根据题目要求，对所选方案进行性质分析（如计算特定场景下的时间复杂度）。

### **典型实例与应用技巧 (Examples & Application Techniques):**
*   **实例1 (2022年真题)**: 在十万级的大数组中，找到最小的10个元素。
    *   **场景分析**: 数据量大，但只需找Top-K，无需完全排序。
    *   **方案对比**:
        *   **A. 简单选择排序**: 循环10次，每次找一个最小的。思想简单，易于描述。时间复杂度为 $O(10 \times N) = O(N)$。
        *   **B. 堆排序**: 建立一个大小为10的大根堆。遍历数组，若元素比堆顶小，则替换堆顶并调整。最优解。时间复杂度为 $O(N \log 10) = O(N)$。
    *   **技巧**: 考场上若想不起最优解（堆），选择次优解（简单选择）并正确分析其复杂度，依然可以获得大部分分数。
*   **实例2 (2019年真题)**: 设计一个空间只增不减的队列。
    *   **场景分析**: 队列需要动态增长。
    *   **方案对比**: 顺序存储（数组）扩容成本高；链式存储天然支持动态增删。
    *   **结论**: 选择链式存储结构。

## 核心原理与解题启发 (Core Principles & Problem-Solving Heuristics)

### **启发1: 输出倒逼输入 (Output Forces Input)**
- 在强化阶段，学习的重心应从被动听课看书，转变为主动做题。通过解题（输出）来检验知识掌握情况，发现薄弱环节后，再带着问题去复习（输入），效率远高于无差别的地毯式复习。

### **启发2: 过程的艺术 (The Art of Process)**
- 数据结构大题的灵魂在于“过程”。无论是应用题还是算法题，能拿高分的关键是能否在脑中或纸上清晰地“导演”出算法执行的每一步。因此，日常训练的核心就是“画图”和“模拟”，把抽象的算法逻辑转化为具体、可视化的步骤。

### **启发3: 笨方法优先，保证得分 (The "Dumb Method" First, Secure Points)**
- 面对有编码要求的算法题，特别是在时间紧张的情况下，首要目标是“做对”，其次才是“做好”。一个逻辑正确但效率较低的暴力解法，远胜于一个构思精妙但最终未能实现或充满bug的最优解。先用“笨方法”确保基础分，有余力再优化。

# 数据结构【应用题】下

#### 1. 核心定义与前提 (Core Definitions & Premises)

*   **应用题答题策略**:
    *   **按需作答**: 题目未明确要求说明理由或给出过程时，可直接给出最终答案以节省时间。
    *   **过程分**: 对于有计算步骤的问题，写出关键步骤。即使最终结果错误，也可能获得过程分。
    *   **举例辅助**: 当用文字抽象描述算法过程困难时，可通过画图举例的方式来辅助说明，以证明自己对知识点的掌握。
*   **考试时间分配**:
    *   **总体**: 3小时考试，建议选择题控制在1-1.5小时，大题留出1.5-2小时。
    *   **大题**: 共7道，平均每道题约17分钟。数据结构和组成原理的大题通常更耗时，每道题不应超过20分钟。应用题应控制在15分钟以内。
*   **408命题特性**:
    *   **选拔性考试**: 题目设计旨在区分不同水平的考生，因此大题通常包含不同难度层次的小问，以拉开分数差距。
    *   **考点重复性**: 历年真题中出现过的考点可能会再次出现，但通常会增加难度或改变考察角度。
    *   **考点创新性**: 命题组也会引入大纲内但从未在综合题中考过的新考点，以考察学生的全面性。
*   **数据结构定义**:
    *   **共享栈 (Shared Stack)**: 两个栈共享同一段连续存储空间（数组），栈底分别设在数组的两端，栈顶向中间增长。
    *   **多项式存储 (Polynomial Storage)**: 使用链表表示多项式，每个节点存储一个非零项的系数 (coefficient) 和指数 (exponent)。
    *   **并查集 (Disjoint Set / Union-Find)**: 一种处理不相交集合的合并与查询问题的数据结构，常用于判断图的连通性问题。其底层通常由一个表示父子关系的数组（双亲表示法）实现。
*   **结构相似性**: 多个看似无关的数据结构在底层实现上具有“数组+链表”的同构模式，例如：
    *   树的孩子表示法 (Child Representation)
    *   图的邻接表 (Adjacency List)
    *   散列表的拉链法 (Chaining Method for Hashing)
    *   基数排序的分配桶 (Buckets in Radix Sort)

#### 2. 定理、原理与定律 (Theorems, Principles & Laws)

*   **从图示到代码原理**: 任何数据结构的`struct`定义都可以通过分析其图形化示意图推导出来，而非死记硬背。核心是识别出结构中的基本单元（节点）和组织形式（数组、指针），然后将其“翻译”成代码。
*   **克鲁斯卡尔 (Kruskal) 算法与并查集**: 克鲁斯卡尔算法在构造最小生成树时，其核心步骤——判断加入一条新的边是否会形成环路——就是通过并查集来实现的。
*   **并查集与图的连通性**:
    *   **判断连通分量**: 遍历图的所有边，对每条边的两个顶点执行合并(union)操作。遍历结束后，并查集中根节点的数量即为连通分量的数量。
    *   **判断环路**: 遍历图的边(u, v)时，若发现u和v在合并前已经属于同一个集合，则说明加入此边会形成环路。

#### 3. 关键公式与方程 (Key Formulas & Equations)

*   **共享栈判满条件**: 假设两个栈顶指针分别为 $top_0$ 和 $top_1$，数组长度为 $MaxSize$。当 $top_0 + 1 == top_1$ 时，栈满。
*   **多项式加法**: $(P_1x^{e_1} + ...) + (P_2x^{e_2} + ...)$。对于指数相同的项，系数相加；指数不同的项，直接保留。

#### 4. 逻辑推导与解题过程 (Logical Derivations & Problem-Solving Processes)

*   **关键路径快速求解法**: 在AOE网（有向无环图）中，从唯一的源点（入度为0）到唯一的汇点（出度为0）的最长路径即为关键路径。该路径的长度决定了工程的最短完成时间。
*   **多项式加法（链表实现）逻辑**:
    1.  使用两个指针 $p_A, p_B$ 分别遍历两个多项式链表A和B。
    2.  比较 $p_A$ 和 $p_B$ 指向节点的指数。
    3.  若指数不同，将指数较小的节点复制到结果链表C中，并将对应指针后移。
    4.  若指数相同，将两个节点的系数相加。若和不为0，则创建一个新节点（系数为和，指数为原指数）插入到C中。然后将 $p_A$ 和 $p_B$ 同时后移。
    5.  当一个链表遍历完后，将另一个链表剩余部分直接连接到C的末尾。
*   **从图示推导`struct`定义的过程**:
    1.  **识别基本单元**: 确定图中最小的、可重复的节点结构。
    2.  **定义节点`struct`**: 分析节点内部包含哪些信息（如数据域、指针域），为每个信息定义一个成员变量。注意指针域的类型应指向它所链接的节点类型。
    3.  **识别组织结构**: 分析这些基本单元是如何被组织起来的（如通过一个数组、一个头指针等）。
    4.  **定义整体结构**: 定义这个组织结构，例如，一个`struct`指针数组。

        1.  初始化并查集，每个顶点自成一个集合。
        2.  遍历图中的每一条边 `(u, v)`。
        3.  检查 `u` 和 `v` 是否已在同一集合中 (`find(u) == find(v)`)。

## 3. 核心思想/主题三：结构同构思想与定义能力强化

### **目标与定义 (Objective & Definition):**
本模块旨在揭示多种高级数据结构在底层实现上的共通模式（“数组+链表”），通过触类旁通，将孤立的知识点串联成网，从根本上提升对复杂数据结构进行定义和理解的能力。

### **关键原理 (Core Principle):**
*   **结构同构 (Structural Isomorphism)**: 树的孩子表示法、图的邻接表、散列表的拉链法、基数排序，尽管应用场景各异，但其数据组织方式均可抽象为**一个提供随机访问入口的“表头数组”**，和**一组处理冲突或多子关系的“节点链表”**。

### **方法论/推导步骤 (Methodology / Derivation Steps):**
1.  **识别“链表节点”**: 首先分析链表中的单个节点需要存储什么信息。例如，邻接表的节点需要存“邻接点下标”和“指向下一个节点的指针”。据此定义出节点`struct`。
2.  **识别“表头数组”**: 再分析数组部分。数组的每个元素是什么？它可能是一个直接指向“链表节点”的指针（如图的邻接表），也可能是一个包含更多信息（如节点数据、指针）的结构体（如树的孩子表示法）。
3.  **组合定义**: 将上述两部分组合起来，形成完整的数据结构定义。

### **典型实例 (Examples):**
*   **图的邻接表**:
    *   **链表节点 (边节点)**: `struct EdgeNode { int adjvex; EdgeNode *next; };`
    *   **表头数组 (顶点节点)**: `struct VertexNode { VertexData data; EdgeNode *firstedge; };`
    *   **整体**: `VertexNode adjList[MAX_VEX];`
*   **散列表拉链法**:
    *   **链表节点**: `struct HashNode { KeyType key; HashNode *next; };`
    *   **表头数组**: `HashNode *hashTable[TABLE_SIZE];`

# 408数据结构算法题

### **1. 核心定义与前提 (Core Definitions & Premises)**

*   **强化阶段学习核心**：知识的输出比输入更重要。主动思考和动手实践是深化理解、建立大脑神经元新连接的关键，直接看答案会抑制思考。
*   **408 算法题**：数据结构大题的组成部分之一，分值为 12-15 分，重点考察代码编写能力。
*   **考试时间限制**：每道大题的平均解题时间不超过 20 分钟。这个限制既是对考生的要求，也是对出题难度的约束。
*   **选拔性考试性质**：题目设计注重区分度，确保不同水平的考生都能拿到相应的分数，不会出现大部分人都无法得分的极端情况。
*   **三元组 (Triplet)**：分别从三个集合 $S_1, S_2, S_3$ 中各取一个元素 $a, b, c$ 组成的单元。
*   **三元组距离 (Triplet Distance)**：三个元素两两之差的绝对值之和，即 $D = \lvert a-b \rvert + \lvert b-c \rvert + \lvert c-a \rvert$。
*   **主元素 (Major Element)**：在数组中出现次数超过元素总数一半的元素。
*   **带权路径长度 (WPL, Weighted Path Length)**：树中所有叶子结点的带权路径长度之和。单个叶子结点的带权路径长度 = 该叶子结点的权值 × 其到根结点的路径长度（深度）。
*   **大纲措辞**：大纲中如出现“基本”二字（如“B+树的基本概念”），意味着该知识点倾向于在选择题中考察，作为大题考察的可能性较低。

### **2. 定理、原理与定律 (Theorems, Principles & Laws)**

*   **完成比完美更重要原则**：在算法题中，优先实现一个能够完成任务的、哪怕是“笨”的解法（暴力解），比追求一个耗时且容易出错的“完美”最优解，得分性价比更高。
*   **乱序问题有序化原理**：对于基于乱序数组的算法题，如果题目未禁止修改数组，可以首先考虑将其排序。排序后的有序性往往能极大地简化问题的后续处理逻辑。
*   **时间与空间权衡原理 (Time-Space Trade-off)**：当题目明确要求“时间上尽可能高效”时，暗示可以牺牲一定的空间复杂度来换取时间复杂度的降低，例如使用辅助数组。
*   **评分相关性原则**：算法的复杂度分析（第三小问）的得分，仅取决于分析结果是否与你所写的代码实现相匹配，而与你的算法本身是否最优无关。
*   **整体复杂度主导原则**：算法的总复杂度由其最高阶的步骤决定。如果算法某部分的复杂度已经很高（如排序的 $O(n \log n)$），那么其他低阶部分（如 $O(n)$ 或 $O(\log n)$）的优化对总复杂度没有影响，无需在这些局部细节上过度优化。

### **3. 关键公式与方程 (Key Formulas & Equations)**

*   **三元组距离公式**:
    $D = \lvert a-b \rvert + \lvert b-c \rvert + \lvert c-a \rvert$
*   **常见时间复杂度**:
    *   暴力三层循环（2020年真题）：$O(n^3)$ 或更精确的 $O(n_1 \cdot n_2 \cdot n_3)$
    *   快速排序 / 归并排序：$O(n \log n)$
    *   单次遍历 / 优化的空间换时间解法：$O(n)$
    *   折半查找：$O(\log n)$
*   **常见空间复杂度**:
    *   快速排序（递归实现）：$O(\log n)$
    *   归并排序：$O(n)$
    *   空间换时间解法（辅助数组）：$O(n)$
*   **单链表倒数第 k 个位置的正向序数**:
    $index = n - k + 1$ (其中 $n$ 为链表总长度)

### **4. 逻辑推导与解题过程 (Logical Derivations & Problem-Solving Processes)**

*   **2020年真题（最小三元组距离）解题思路**:
    1.  **暴力解（笨蛋解法，可得约 9-10 分）**：
        *   Step 1: 使用三层嵌套 for 循环，分别遍历三个数组 $S_1, S_2, S_3$。
        *   Step 2: 在最内层循环中，获得一个完整的三元组 $(a,b,c)$。
        *   Step 3: 计算该三元组的距离 $D$。
        *   Step 4: 使用一个全局变量记录并更新遇到的最小距离。
        *   Step 5: 遍历所有组合后，返回最小距离。时间复杂度为 $O(n^3)$。
    2.  **最优解思路**: 利用数组已排序的特性，优化指针的移动逻辑（此处未详述，但指明了优化方向）。

*   **2018年真题（未出现的最小正整数）解题思路**:
    1.  **次优解（可得 11-12 分）**：
        *   Step 1: 判断题目未禁止修改数组，因此可以排序。
        *   Step 2: 手写或调用快速排序算法，将乱序数组变为有序。时间复杂度 $O(n \log n)$。
        *   Step 3: 遍历排序后的数组，从第一个正数开始检查，寻找第一个不连续的数值。例如，如果当前值为 $x_i$，下一个值为 $x_{i+1}$，若 $x_{i+1} \gt  x_i + 1$，则 $x_i+1$ 即为所求。时间复杂度 $O(n)$。
        *   Step 4: 总体复杂度为 $O(n \log n)$。
    2.  **最优解（空间换时间，满分）**：
        *   Step 1: 题目强调“时间上”高效，暗示可用空间换时间。
        *   Step 2: 创建一个长度为 $n+2$ 的辅助标记数组 `b`。
        *   Step 3: 遍历原数组 `a`，对于 `a` 中每个值为 $x$ 的正数（且 $x \le n+1$），将 `b[x]` 标记为 1。时间复杂度 $O(n)$。
        *   Step 4: 遍历标记数组 `b`，从下标 1 开始，找到第一个值为 0 的元素的下标，该下标即为未出现的最小正整数。时间复杂度 $O(n)$。
        *   Step 5: 总体时间复杂度 $O(n)$，空间复杂度 $O(n)$。

*   **链表原地逆置过程（头插法）**:
    1.  **初始化**：指针 `p` 指向待处理的第一个节点（如 `a2`），指针 `q` 指向其前驱（如 `a1`）。
    2.  **摘除节点**：修改 `q` 的 `next` 指针，使其指向 `p` 的 `next` 节点，从而将 `p` 所指节点从链表中摘除。
    3.  **头插节点**：将 `p` 所指节点的 `next` 指向头结点 `H` 的后继，然后将 `H` 的 `next` 指向 `p`。
    4.  **迭代**：移动指针，重复上述过程，直到所有节点都被处理。

*   **2019年真题（链表重排）解题思路**:
    1.  **Step 1 (找中点)**: 遍历链表，找到中间节点，将链表拆分为前后两半。
    2.  **Step 2 (后半段逆置)**: 对后半段链表应用“头插法”，实现原地逆置。
    3.  **Step 3 (逐点合并)**: 同时遍历前半段和逆置后的后半段，将后半段的节点逐一插入到前半段对应节点的后面。

    *   考研算法题对代码的健壮性要求不高，允许存在一些小的、不影响核心逻辑的 bug，阅卷组会“能给尽给”，但核心思路必须正确。
    *   需要自己整理并熟练掌握一套手写代码模板，尤其是快速排序。

    *   **少食多餐**：写代码需要保持手感，建议每天花少量时间（如20-30分钟）进行持续练习，而不是长时间集中突击。
    *   **分模块训练**：按照顺序表、链表、树、图的顺序，逐个模块进行专项训练，稳步推进。

*   **核心思想**:
    1.  **暴力也是一种智慧 (Brute Force Wisdom)**：在有限时间内，一个稳定拿分的暴力解或次优解，远胜于一个没有把握的最优解。
    2.  **化未知为已知 (Reduction)**：通过预处理（如排序）或数据结构转换（如将顺序存储的树逻辑上视为链式递归处理），将复杂或不熟悉的问题转化为简单、熟悉的问题模式。
    3.  **基本功是所有技巧的基石 (Fundamental Skills)**：无论题目如何变化，对数据结构（尤其是链表和树）的基本操作（遍历、增、删、改）的熟练掌握是解题的根本。

*   **核心主题**:
    1.  **排序思想的应用**：以快速排序为代表的高效排序算法在处理顺序表问题中的泛用性。
    2.  **链表指针操作**：链表问题的核心在于指针的灵活、准确操作。
    3.  **递归在树形结构中的应用**：树相关的问题几乎都可以通过设计巧妙的递归遍历函数来解决。

*   **核心题型**:
    1.  **基于顺序表的算法题**：通常涉及排序、查找、或基于特定规则的元素重排与统计。
    2.  **基于链表的算法题**：考察对单链表节点的拆分、链接、重排等基本操作的组合应用。
    3.  **基于树与二叉树的算法题**：核心是递归遍历，并在此过程中计算树的属性（如WPL、高度）或判断树的形态（如BST、完全二叉树）。
    4.  **基于图的算法题**：目前主要考察对图的邻接矩阵表示的理解和遍历。

## 1. 核心题型一：基于顺序表（数组）的算法

### **目标与定义 (Objective & Definition):**

本模块旨在解决在给定顺序表（数组）上进行查找、排序、统计或变换的问题。数组可能乱序或有序，解题的关键通常在于如何高效地利用或创建序列的有序性。

*   **核心定义**:
    *   **乱序数组**：元素排列无特定顺序的数组。
    *   **有序数组**：元素按升序或降序排列的数组。
    *   **主元素**：数组中出现次数超过总元素数一半的元素。

### **关键原理与公式 (Core Principles & Formulas):**

*   **核心原理**:
    1.  **乱序问题有序化**: 当题目给出乱序数组且未禁止修改时，优先考虑“先排序，再处理”的思路。
    2.  **时间空间权衡**: 当题目强调“时间上高效”时，可大胆使用辅助数组等额外空间来优化时间性能。
*   **关键公式 (复杂度)**:
    *   **暴力解（多层循环）**: 时间复杂度通常为 $O(n^2)$ 或 $O(n^3)$。
    *   **排序预处理**:
        *   快速排序: 时间 $O(n \log n)$, 空间 $O(\log n)$。
        *   归并排序: 时间 $O(n \log n)$, 空间 $O(n)$。
    *   **空间换时间解**: 时间 $O(n)$, 空间 $O(n)$。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

1.  **Step 1: 审题** - 判断数组是乱序还是有序？题目对时间/空间复杂度有无特殊要求？是否禁止修改原数组？
2.  **Step 2: 构思暴力解** - 首先思考最直观的解法（如多层循环），确保有一个保底方案。这能让你拿到大部分分数。
3.  **Step 3: 寻求优化**
    *   **路径一 (排序)**: 如果数组乱序，思考“排序后问题是否会变得更简单？”。如果答案是肯定的，则选择 **快速排序** 作为预处理步骤。
    *   **路径二 (空间换时间)**: 如果题目只要求时间高效，思考“能否用一个辅助数组（如哈希表、标记数组）来记录信息，从而将查找时间从 $O(n)$ 降至 $O(1)$？”。
4.  **Step 4: 编码实现** - 根据选择的路径编写代码，优先选择自己最熟悉、最不容易出错的算法（如熟练的快排模板）。
5.  **Step 5: 分析复杂度** - 根据代码，准确写出对应的时间和空间复杂度。

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **实例1 (2018年真题 - 寻找未出现的最小正整数)**:
    *   **问题**: 给定乱序整数数组，找未出现的最小正整数。
    *   **次优解 (排序法)**: 先用快速排序将数组变为有序，然后一次遍历即可找到答案。这是“乱序问题有序化”的典型应用。
    *   **最优解 (空间换时间)**: 新建一个标记数组，遍历原数组，标记出现过的正整数。再遍历标记数组，找到第一个未被标记的数。这是“时间空间权衡”的典型应用。
*   **实例2 (2013年真题 - 寻找主元素)**:
    *   **问题**: 寻找出现次数过半的元素。
    *   **应用技巧**: 对乱序数组排序后，如果存在主元素，它必然出现在数组的中点位置（下标为 $\lfloor n/2 \rfloor$）。因此，排序后只需检查中点元素出现的次数是否过半即可。
*   **技巧总结**: **快速排序是顺序表问题的“瑞士军刀”**。务必准备一份能够熟练默写、简洁高效的快排代码模板，它能解决大部分需要排序的场景。

## 2. 核心题型二：基于链表的算法

### **目标与定义 (Objective & Definition):**

本模块旨在解决对单链表进行结构修改、节点查找和重排的问题。由于链表无法随机存取，其核心考察点是对指针的精准操作和遍历技巧。

*   **核心定义**:
    *   **原地逆置**: 在不使用额外节点空间的情况下，将链表 `a1->a2->...->an` 变为 `an->...->a2->a1`。
    *   **前后指针**: 使用两个间隔固定或不固定的指针同步在链表中移动，以完成特定任务。

### **关键原理与公式 (Core Principles & Formulas):**

*   **核心原理**:
    1.  **基本功至上**: 链表题不考察复杂算法，而是考察对节点的**遍历、查找、摘除、插入**等基本操作的熟练组合。
    2.  **指针即一切**: 解题过程就是一系列指针的断开与重连，画图辅助理解指针变化至关重要。
*   **关键操作**:
    *   **头插法**: 可实现链表的原地逆置。
    *   **尾插法**: 可在移动节点时保持原有相对顺序。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

1.  **Step 1: 画图** - 根据题意，画出初始链表状态和目标链表状态的示意图。
2.  **Step 2: 拆解任务** - 将复杂的链表变换任务，拆解为若干个基本操作的组合（如：找到中点 -&gt; 拆分 -&gt; 逆置 -&gt; 合并）。
3.  **Step 3: 设计指针** - 思考需要几个指针来完成任务。是否需要前驱指针？是否需要快慢指针？
4.  **Step 4: 编码实现** - 将图上模拟的指针操作，一步步翻译成代码。要特别注意处理边界条件（如空链表、单节点链表）和指针丢失问题（在断开链接前要保存好后继节点）。

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **实例1 (2019年真题 - 链表重排)**:
    *   **问题**: 将链表 `L = {a1, a2, ..., an}` 重新排序为 `{a1, an, a2, an-1, ...}`。
    *   **应用技巧**: 完美演绎了任务拆解。① 快慢指针法找到链表中点。② 拆分为两个子链表。③ 对后一个子链表使用**头插法**进行原地逆置。④ 归并两个子链表。
*   **实例2 (2009年真题 - 查找倒数第k个节点)**:
    *   **应用技巧**: 使用**前后双指针**（或快慢指针）技巧。让快指针先走 `k` 步，然后快慢指针同步前进。当快指针到达链表末尾时，慢指针所指的位置即为倒数第 `k` 个节点。此方法仅需一次遍历，比“先遍历求长度再遍历查找”的方法更优。

## 3. 核心题型三：基于树与二叉树的算法

### **目标与定义 (Objective & Definition):**

本模块旨在解决基于二叉树（或树）结构进行属性计算、形态判断和遍历输出的问题。递归是处理树形结构最自然、最核心的工具。

*   **核心定义**:
    *   **递归遍历**: 包括先序、中序、后序三种基本的遍历方式。
    *   **带权路径长度 (WPL)**: 所有叶子结点的（权值 × 深度）之和。

### **关键原理与公式 (Core Principles & Formulas):**

*   **核心原理**:
    1.  **万物皆遍历**: 几乎所有的二叉树算法题，其核心都是一个修改版的**递归遍历**算法（先序、中序或后序）。
    2.  **分治思想**: 将对整棵树的问题，分解为对当前节点的操作，以及对左、右子树的同样问题的递归求解。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

1.  **Step 1: 确定遍历顺序** - 根据问题性质，思考在“根、左、右”三个处理时机中，应在哪一步执行核心操作。
    *   中序遍历常用于与二叉排序树相关的问题。
2.  **Step 2: 设计递归函数** - 定义递归函数的签名（参数和返回值）。
    *   **通过参数传递信息**: 自顶向下传递信息（如当前节点的深度）。
    *   **通过返回值传递信息**: 自底向上传递子树的计算结果（如子树的高度）。
    *   **通过全局变量**: 记录需要在整个递归过程中共享和累加的状态（如WPL的总和）。
3.  **Step 3: 确定递归基 (Base Case)** - 明确递归的终止条件，通常是节点为空（`node == NULL`）。
4.  **Step 4: 编写递归体** - 组合对当前节点的操作和对左、右子树的递归调用。

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **实例1 (2014年真题 - 计算WPL)**:
    *   **问题**: 计算一棵二叉树的带权路径长度。
    *   **应用技巧**: 采用先序遍历。设计递归函数 `calculateWPL(Node* node, int depth)`。
        *   **参数传递**: 将当前节点的深度 `depth` 作为参数，自顶向下传递。
        *   **全局变量**: 使用一个全局变量 `totalWPL`。
        *   **核心逻辑**: 在递归函数中，判断当前节点是否为叶子节点。如果是，则计算 `node->weight * depth` 并累加到 `totalWWPL` 中。
*   **实例2 (判断一棵树是否为二叉排序树)**:
    *   **应用技巧**: 利用二叉排序树**中序遍历**结果为递增序列的特性。对树进行中序遍历，并用一个变量记录前一个被访问的节点值，检查当前节点值是否始终大于前一个值。

*   **`typedef` 关键字**：其本质是类型重命名，用于将复杂或冗长的类型名（如 `struct tree_node`）替换为一个更简洁的别名（如 `TNode`），以简化代码书写。
*   **变量作用域**：在一个代码块（如 `if` 语句的 `{}` 内）定义的变量，其作用范围仅限于该代码块，在外部无法访问。

### **2. 定理、原理与定律 (Theorems, Principles & Laws)**

*   **可视化编码原理**：在编写代码前，通过在纸上画出数据结构实例（如数组、链表、树）并标注下标或指针，可以极大地帮助理清逻辑、确定边界条件，是避免错误的关键步骤。
*   **代码思维的迭代本质**：编写代码是一个动态的、边想边做的过程，而非线性的“先想好一切再写”。通常是先搭建框架，在实现过程中发现需要新的变量或逻辑时再进行补充和完善。
*   &lt;strong&gt;代码可读性的相对性原理&lt;/strong&gt;：代码的可读性是相对于读者而言的。对于中国考生和阅卷老师，使用符合中文逻辑的拼音命名变量（如 `qidian`, `jindu`）并加以注释，可以提升对自己和阅卷老师的可读性，是一种有效的应试策略。
*   **`for` 循环与 `while` 循环的等价性**：两者在逻辑上完全等价。对于初学者，`while` 循环将初始化、循环条件、循环体和迭代更新步骤在代码中顺序分开，可能更符合线性的阅读和思考习惯。
*   **BST 查找原理**：利用二叉搜索树（BST）左子树 &lt; 根节点 &lt; 右子树的特性，每次比较可以将搜索范围缩小一半，从而实现高效查找。

### **3. 关键公式与方程 (Key Formulas & Equations)**

*   **折半查找中点计算**:
    $mid = l + (r - l) / 2$ （此形式可有效防止 `l+r` 溢出，虽然在408考试中不作强制要求，但 `mid = (l+r)/2` 是基础形式）
*   **顺序查找（模式匹配）外层循环边界**:
    主串的起始匹配点 `i` 的范围为 $0 \le i \le n-m$，其中 $n$ 为主串长度，$m$ 为模式串长度。

### **4. 逻辑推导与解题过程 (Logical Derivations & Problem-Solving Processes)**

*   **顺序查找（数组模式匹配）实现过程**:
    1.  **外层循环**：用一个变量 `起点` (qidian) 遍历主串 `A` 中所有可能的起始位置（从 `0`到 `n-m`）。
    2.  **内层循环**：对每一个 `起点`，用一个变量 `进度` (jindu) 从 `0` 开始，同时遍历模式串 `B` 和主串 `A` 从 `起点` 开始的子串。
    3.  **匹配逻辑**：在内层循环中，比较 `A[起点 + 进度]` 与 `B[进度]` 是否相等。
    4.  **失败处理**：一旦出现不相等，立即使用 `break` 关键字跳出内层循环，进入外层循环的下一次迭代（`起点++`）。
    5.  **成功判断**：如果内层循环正常结束（即 `进度` 增长到了 `m`），说明模式串完全匹配。此时记录下当前的 `起点` 值。
    6.  **返回首次成功位置**：一旦找到第一个匹配，即可记录结果并跳出外层循环，或直接 `return` 结果。

*   **顺序查找（链表模式匹配）实现过程**:
    1.  **外层循环指针**：`起点` 指针，从主串链表的第一个数据节点开始，每次向后移动 (`起点 = 起点->next`)。
    2.  **内层循环指针**：需要一个临时指针 `p` (初始化为 `起点`) 和一个 `进度` 指针 (初始化为模式串的第一个数据节点)，两个指针同步后移。
    3.  **索引跟踪**：由于链表没有原生下标，需额外定义一个整型变量 `下标` (xiaobiao)，与 `起点` 指针同步 `++`，用于记录当前匹配起点的位序。
    4.  **成功/失败逻辑**：与数组版本类似，通过 `进度` 指针是否到达 `NULL` 来判断内层循环是否匹配成功。

*   **折半查找（寻找首次出现位置）实现过程**:
    1.  **初始化**：设置左、右指针 `l=0`, `r=n-1`，以及一个结果变量 `下标 = -1`。
    2.  **循环条件**：`while (l <= r)`。
    3.  **计算中点**：`mid = (l+r)/2`。
    4.  **比较与收缩**：
        *   若 `A[mid] < k`，则在右半区查找：`l = mid + 1`。
        *   若 `A[mid] > k`，则在左半区查找：`r = mid - 1`。
        *   若 `A[mid] == k`：**这是关键**。找到了一个匹配项，将 `mid` 存入 `下标` 变量，然后为了寻找**首次**出现的位置，必须尝试在**左半区**继续查找更早的匹配项，故执行 `r = mid - 1`。
    5.  **返回结果**：循环结束后，`下标` 变量中存储的就是首次出现的位置，若从未匹配过则为初始值 `-1`。

*   **二叉搜索树（BST）查找与插入实现过程**:
    *   **非递归（循环）查找**:
        1.  初始化指针 `p = root`。
        2.  循环 `while (p != NULL)`。
        3.  比较 `k` 与 `p->data`：相等则找到，`return p`；`k` 更小则 `p = p->left`；`k` 更大则 `p = p->right`。
        4.  若循环结束，说明未找到，`return NULL`。
    *   **递归查找**:
        1.  **基准情况**：若 `root == NULL`，返回 `NULL`。若 `root->data == k`，返回 `root`。
        2.  **递归步骤**：若 `k < root->data`，`return search(root->left, k)`；若 `k > root->data`，`return search(root->right, k)`。
    *   **带插入功能的查找**:
        1.  在查找过程中，当需要移动到某个 `left` 或 `right` 子节点但发现其为 `NULL` 时，即找到了插入位置。
        2.  在该位置 `malloc` 一个新节点，填入数据 `k`，并将其链接到父节点的 `left` 或 `right` 指针上。

### **5. 应用技巧与注意事项 (Application Techniques & Critical Caveats)**

*   **手写代码习惯**：
    *   **搭建框架先行**：写 `while` 循环时，先写好初始化、循环条件和末尾的迭代更新语句，形成框架，再填充核心逻辑，可防止遗漏迭代步骤导致死循环。
    *   **利用 `break`**：当循环的某个条件一旦满足就需要立即终止时（如模式匹配中出现字符不匹配），`break` 是一个非常有效的工具。
*   **变量命名技巧**：对于编程不熟练的考生，使用拼音（如 `qidian`）或简单的英文单词（如 `start`）作为变量名，比使用无意义的 `i, j, k` 更能帮助自己在紧张的考试中保持思路清晰。
*   **处理重复元素**：在折半查找等算法中，要特别注意题目是否要求“首次”或“末次”出现。这决定了当找到一个匹配项后，是继续向左搜索还是向右搜索。
*   **题目改造与拓展**：408 算法题常在基础算法上进行拓展以增加区分度。例如，将“查找”拓展为“查找失败则插入”。备考时应训练这种思维，思考基础算法的变种形式。
*   **递归与非递归**：对于树的遍历和查找，递归写法通常更简洁直观，但非递归（循环）写法也是必须理解的。两者在逻辑上等价，选择自己更熟练、更不容易出错的方式即可。

## 1. 核心题型一：顺序查找与字符串模式匹配

### **目标与定义 (Objective & Definition):**

本模块旨在解决在一个序列（数组或链表）中，通过逐一比较的方式，定位一个子序列（模式串）首次出现位置的问题。这是对顺序查找最直接且最常见的考察形式。

*   **核心定义**:
    *   **主串**：被查找的那个较长的字符串。
    *   **模式串**：需要去定位的那个较短的字符串。
    *   **顺序查找**：从序列的第一个元素开始，依次向后比较，直到找到目标或到达序列末尾。

### **关键原理与公式 (Core Principles & Formulas):**

*   **核心原理**:
    1.  **双层遍历逻辑**：外层循环控制主串的“匹配起始点”，内层循环负责从该起始点开始，与模式串进行逐字符的比较。
    2.  **可视化驱动编码**：写代码前，必须在纸上画出主串和模式串的示意图，并手动模拟指针（或下标）的移动过程，这能极大简化逻辑思考和边界判断。
*   **关键边界**:
    *   对于数组：外层循环的 `起点` 范围为 `0` 到 `n-m`。
    *   对于链表：外层循环的 `起点` 指针的终止条件是 `起点 != NULL`。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

1.  **Step 1: 准备与画图** - 在草稿纸上画出题目给出的主串和模式串实例，并标好下标/画出指针。
2.  **Step 2: 定义关键变量** - 至少需要两个核心变量/指针：
    *   `起点` (start)：控制外层循环，指向主串中本轮匹配的起始位置。
    *   `进度` (progress)：控制内层循环，用于遍历模式串。
    *   (链表特有) `下标` (index)：一个整型变量，与 `起点` 指针同步移动，用于记录位序。
3.  **Step 3: 搭建外层循环** - 遍历所有可能的 `起点`。
    *   `while (起点 <= n-m)` 或 `while (起点 != NULL)`。
    *   在循环末尾，确保 `起点` 会向前推进（`起点++` 或 `起点 = 起点->next`）。
4.  **Step 4: 实现内层匹配逻辑** - 对每个 `起点`，进行逐字符比较。
    *   启动一个内层循环，让 `进度` 指针从头开始遍历模式串。
    *   在循环中，比较主串和模式串的对应字符。
    *   如果字符**不匹配**，立即 `break` 掉内层循环，本轮匹配失败。
5.  **Step 5: 判断成功与返回** - 在内层循环结束后，检查其是如何结束的。
    *   如果 `进度` 走完了整个模式串（例如 `进度 == m`），说明匹配成功。
    *   记录下成功的 `起点` 或 `下标`，然后可以 `break` 外层循环或直接 `return`。
6.  **Step 6: 处理完全失败** - 如果外层循环正常结束而从未成功过，返回 `-1` 或 `NULL`。

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **实例**: 分别实现基于数组和基于单链表的字符串模式匹配。
*   **应用技巧**:
    *   **变量命名**: 使用 `qidian` (起点), `jindu` (进度) 等拼音或易于理解的词汇命名，可以减少思考时的认知负担。
    *   **框架优先**: 编写 `while` 循环时，先把 `初始化`、`循环条件`、`末尾迭代` 三个要素写好，再填充中间的逻辑，能有效避免死循环。
    *   **链表指针保护**: 在链表匹配中，不要直接移动 `起点` 指针进行内层比较，而是用一个临时指针 `p = 起点` 来完成，以保证外层循环的 `起点` 指针能正确地逐一后移。

## 2. 核心题型二：有序序列的折半查找

### **目标与定义 (Objective & Definition):**

本模块旨在解决在**有序顺序表（数组）**中，高效地查找指定元素 `k` 的问题。核心考察点在于处理存在重复元素时，如何精确找到“首次”或“末次”出现的位置。

*   **核心定义**:
    *   **折半查找（二分查找）**：通过不断将搜索区间一分为二来进行查找的算法，前提是序列必须有序且支持随机访问。

### **关键原理与公式 (Core Principles & Formulas):**

*   **核心原理**:
    1.  **区间收缩**: 维护一个由 `l` 和 `r` 指针界定的闭区间 `[l, r]` 作为搜索范围。根据中点 `mid` 处元素与 `k` 的比较结果，将区间缩小一半。
    2.  **“找到但不停止”**: 当题目要求查找首次/末次出现位置时，即使在中点找到了 `k`，也不能立即停止，而是要记录该位置，并继续在可能出现更早/更晚位置的那个半区继续搜索。
*   **关键公式**:
    *   中点计算: `mid = l + (r - l) / 2`
    *   寻找**首次**出现：当 `A[mid] == k` 时，记录 `mid`，并向**左半区**收缩 `r = mid - 1`。
    *   寻找**末次**出现：当 `A[mid] == k` 时，记录 `mid`，并向**右半区**收缩 `l = mid + 1`。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

1.  **Step 1: 初始化** - 定义 `l=0`, `r=n-1`。定义一个结果变量 `ans = -1` 用来存储最终找到的下标。
2.  **Step 2: 搭建循环** - `while (l <= r)`。
3.  **Step 3: 计算中点** - `mid = ...`。
4.  **Step 4: 核心比较与区间收缩**
    *   `if (A[mid] < k)`: `l = mid + 1`
    *   `else if (A[mid] > k)`: `r = mid - 1`
    *   `else (A[mid] == k)`:
        *   `ans = mid;` // 暂存当前找到的位置
        *   根据目标（首次/末次）执行 `r = mid - 1` 或 `l = mid + 1`。
5.  **Step 5: 返回结果** - 循环结束后，`ans` 中保存的就是最终结果。

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **实例**: 在有序数组 `{..., 5, 5, 5, ...}` 中查找数字 `5` 首次出现的位置。
*   **应用技巧**: 使用一个额外的变量（如 `ans` 或 `下标`）来“记住”最后一次成功找到 `k` 的位置是该解法的精髓。这个变量的初始值设为 `-1`，巧妙地处理了查找失败的情况。

## 3. 核心题型三：二叉搜索树（BST）的操作

### **目标与定义 (Objective & Definition):**

本模块旨在解决在二叉搜索树（BST）中查找指定值 `k`，并可能伴随“查找失败则插入”的拓展要求。考察的是对 BST 特性的利用以及树形结构的递归或迭代处理能力。

### **关键原理与公式 (Core Principles & Formulas):**

*   **核心原理 (BST 特性)**: 对任意节点，其左子树所有节点的值均小于该节点的值，右子树所有节点的值均大于该节点的值。这是指导查找路径的唯一依据。
*   **递归与分治**: 将在整棵树中查找的问题，分解为“在当前节点比较”和“在左/右子树中查找”的子问题。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

*   **方法一：非递归（迭代）实现**
    1.  **Step 1: 初始化** - `Node* p = root;`
    2.  **Step 2: 循环查找** - `while (p != NULL)`
    3.  **Step 3: 比较与移动**
        *   `if (k == p->data)`: 找到，`return p`。
        *   `if (k < p->data)`: 向左走，`p = p->left`。
        *   `else`: 向右走，`p = p->right`。
    4.  **Step 4: 查找失败** - 循环结束，`return NULL`。

*   **方法二：递归实现**
    1.  **Step 1: 基准条件（递归出口）**
        *   `if (root == NULL)`: 查找失败，`return NULL`。
        *   `if (k == root->data)`: 查找成功，`return root`。
    2.  **Step 2: 递归深入**
        *   `if (k < root->data)`: `return search(root->left, k);`
        *   `else`: `return search(root->right, k);`

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **实例**: 实现一个 BST 查找函数，若未找到值为 `k` 的节点，则创建该新节点并插入到正确位置。
*   **应用技巧（如何在查找中插入）**:
    *   在**非递归**版本中，当下一步要移动到 `p->left` 或 `p->right` 但发现其为 `NULL` 时，就找到了插入点。此时创建新节点，并将其链接到 `p->left` 或 `p->right`。
    *   在**递归**版本中，当 `root == NULL` 时，不仅是查找失败的信号，也是递归创建并返回新节点的时机。

# 排序算法核心知识与应用解析

### **1. 核心定义与前提 (Core Definitions & Premises)**

*   **直接插入排序 (Direct Insertion Sort)**: 将一个记录插入到已经排好序的有序表中，从而得到一个新的、记录数增一的有序表。对于顺序表，通过逐个比较和后移元素来找到插入位置；对于链表，则是通过遍历找到插入位置并修改指针。
*   **折半插入排序 (Binary Insertion Sort)**: 与直接插入排序类似，但使用折半查找来确定新元素的插入位置，以减少比较次数。
*   **冒泡排序 (Bubble Sort / 起泡排序)**: 通过重复遍历要排序的数列，一次比较两个元素，如果他们的顺序错误就把他们交换过来。
*   **简单选择排序 (Simple Selection Sort)**: 每一轮在待排序的记录中选出关键字最小（或最大）的记录，顺序放在已排好序的子序列的最后，直到全部待排序记录排完。
*   **堆 (Heap)**: 逻辑上是一棵完全二叉树，物理上用数组存储。分为大根堆（父节点值大于等于子节点值）和小根堆（父节点值小于等于子节点值）。
*   **算法稳定性 (Algorithm Stability)**: 如果待排序的序列中存在多个关键字相同的元素，排序后这些元素的相对位置保持不变，则称该排序算法是稳定的。
*   **原地工作 (In-place Algorithm)**: 指算法在执行过程中，所占用的额外内存空间是常数级别的，即空间复杂度为 $O(1)$。
*   **前提与假设**:
    *   **考试重点**: 408 考试中，算法题不限制解题手段，但通常会考察对基本数据结构（特别是链表）的操作。
    *   **算法实用性评估**:
        *   折半插入排序：虽然查找时间开销降低，但移动元素的时间开销仍为 $O(n)$，整体性能提升有限，算法题应用价值不高。
        *   希尔排序、基数排序、外部排序：代码实现复杂，在算法大题中直接考察编写代码的可能性极低。
        *   堆排序：代码量大，直接考察完整实现的可能性不高，但可能考察其特性，如判断一个数组是否为堆。
    *   **链表排序策略**: 对于链表排序，直接插入排序和简单选择排序是实现相对简单且有效的常用方法。

### **2. 定理、原理与定律 (Theorems, Principles & Laws)**

*   **算法复杂度原理**: 算法的最终评分取决于其**整体时间复杂度**，而非局部操作的优化。例如，折半插入排序虽然优化了查找部分，但未改变移动元素的 $O(n)$ 复杂度，故整体复杂度并未降低数量级。
*   **链表操作原理**: 对单链表进行插入或删除操作时，必须定位到目标节点的前驱节点，才能修改其 `next` 指针。因此，使用“前驱-当前”双指针同步遍历是一种核心技巧。
*   **头插法原理**: 在一个链表的头部（头结点之后）连续插入新节点。对于构建一个升序链表，如果每次都将待排序序列中的**最大**元素通过头插法插入，最终形成的链表就是升序的。

### **3. 关键公式与方程 (Key Formulas & Equations)**

*   **折半查找时间复杂度**: $O(\log_2 n)$
*   **直接插入排序时间复杂度**: $O(n^2)$
*   **折半插入排序时间复杂度**: 查找部分为 $O(\log_2 n)$，移动部分为 $O(n)$，总时间复杂度仍为 $O(n^2)$。
*   **冒泡排序时间复杂度**: $O(n^2)$
*   **简单选择排序时间复杂度**: $O(n^2)$
*   **快速排序平均时间复杂度**: $O(n \log_2 n)$
*   **堆的父子节点索引关系 (数组从0开始)**:
    *   对于下标为 $i$ 的节点：
    *   左孩子下标: $2i + 1$
    *   右孩子下标: $2i + 2$
*   **完全二叉树分支节点范围**: 对于一个包含 $n$ 个节点、下标从 $0$ 到 $n-1$ 的完全二叉树，其最后一个分支节点的下标为 $\lfloor \frac{n}{2} \rfloor - 1$ 或 $(\frac{n-1}{2})$ 的整数部分。

### **4. 逻辑推导与解题过程 (Logical Derivations & Problem-Solving Processes)**

*   **顺序表直接插入排序过程**:
    1.  外层循环从第二个元素（下标 $i=1$）开始，直到最后一个元素。
    2.  将当前待处理元素 `A[i]` 存入临时变量 `temp`。
    3.  内层循环（或指针 `j`）从 `i-1` 开始向前扫描。
    4.  若 `A[j] > temp`，则将 `A[j]` 后移一位至 `A[j+1]`，`j` 继续前移。
    5.  循环终止于 `A[j] <= temp` 或 `j` 小于0。
    6.  将 `temp` 插入到 `A[j+1]` 位置。

*   **单链表简单选择排序 (头插法) 过程**:
    1.  创建一个新的空链表（只有头结点），用于存放排序结果。
    2.  将原链表视为待排序序列。
    3.  当待排序序列不为空时，循环执行以下操作：
        a. 遍历待排序序列，找到值最大的节点 `p_max` 及其前驱节点 `pre_max`。
        b. 将 `p_max` 节点从待排序序列中拆卸下来（通过 `pre_max->next = p_max->next`）。
        c. 将 `p_max` 节点通过头插法插入到新链表的头部。
    4.  循环结束后，新链表即为排好序的结果。

*   **判断数组是否为大根堆的过程**:
    1.  确定最后一个分支节点的下标（例如 $\lfloor \frac{n}{2} \rfloor - 1$）。
    2.  从第一个节点（下标0）遍历到最后一个分支节点。
    3.  对于每个分支节点 `A[i]`，检查其与左右孩子的关系：
        a. 检查左孩子是否存在且 `A[i]` 是否小于 `A[2i+1]`。
        b. 检查右孩子是否存在且 `A[i]` 是否小于 `A[2i+2]`。
    4.  只要发现任何一个分支节点不满足大根堆性质（小于其任一孩子），即可判定该数组不是大根堆。
    5.  如果所有分支节点都满足性质，则该数组是大根堆。

### **5. 应用技巧与注意事项 (Application Techniques & Critical Caveats)**

*   **代码封装**: 对于重复出现的操作（如创建节点、交换变量、头插法），可以将其封装成一个独立的函数，使主代码更简洁、可读性更高。
*   **双指针法**: 在单链表中，使用 `pre` 和 `p` 两个指针同步后移，是进行节点查找、插入、删除操作的标准且高效的技巧。
*   **边界条件处理**:
    *   **数组越界**: 在访问数组元素前，必须检查下标是否在合法范围内（如判断堆的右孩子是否存在）。
    *   **空指针**: 在访问指针指向的成员（如 `p->data`）前，必须确保指针 `p` 不为 `NULL`。
    *   **链表为空或单元素**: 排序前应先判断链表是否为空或只有一个元素，这些情况下无需排序，直接返回。
*   **“偷袭”解法 (空间换时间)**: 如果题目未限制空间复杂度为 $O(1)$，可以将链表元素复制到数组中，使用高效的数组排序算法（如快速排序）排序后，再将结果写回链表。这是一种在时间效率上占优的实用技巧。
*   **添加临时头结点**: 在处理一个没有头结点的（子）链表时，可以手动创建一个临时头结点指向它，从而统一对链表（包括第一个元素的）操作逻辑，避免复杂的边界情况判断。

### **6. 核心思想、主题与题型 (Core Ideas, Themes & Problem Types)**

*   **核心主题1：顺序存储结构 (数组) 的排序**: 考察在连续内存空间上如何通过元素移动和交换实现排序，如直接插入排序和冒泡排序。
*   **核心主题2：链式存储结构 (链表) 的排序**: 考察在离散内存空间上如何通过修改指针实现排序，这是408考试的重点和难点。重点方法包括直接插入法和选择排序的链表改造。
*   **核心思想1：算法的适配与改造**: 将为数组设计的经典排序思想（如插入、选择）适配到链表结构上，并根据链表特性（只能顺序访问、操作指针）进行代码层面的改造。
*   **核心思想2：模块化与抽象**: 将链表排序中的核心原子操作（如“在有序链表中插入一个节点”、“头插法”）抽象并封装成独立的辅助函数，以此构建更复杂的算法。
*   **核心题型1：原地排序 (In-place Sorting)**: 特别是对于链表，题目常要求在 $O(1)$ 的额外空间复杂度下完成排序，排除了“数组中转”等高空间消耗的方法。
*   **核心题型2：数据结构性质检验**: 不直接考察复杂算法的实现，而是考察对该结构核心性质的理解，如“判断一个数组是否为大根堆”。

## 1. 核心主题一: 基于顺序表 (数组) 的排序算法

### **目标与定义 (Objective & Definition):**

本模块旨在解决如何在连续存储的数组结构上，通过元素值的比较、移动和交换，实现序列的有序化。

*   **直接插入排序**: 将当前元素插入到其左侧已排序部分的正确位置。
*   **冒泡排序**: 通过相邻元素的反复比较和交换，使最大（或最小）的元素像气泡一样“浮”到序列的一端。

### **关键原理与公式 (Core Principles & Formulas):**

*   **原理**: 数组排序的核心在于通过下标直接访问元素，并通过数据搬移（插入排序）或交换（冒泡排序）来调整元素位置。
*   **公式**:
    *   时间复杂度: 两种算法在最坏和平均情况下的时间复杂度均为 $O(n^2)$。
    *   空间复杂度: 均为 $O(1)$，属于原地排序。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

**直接插入排序 (Direct Insertion Sort):**

1.  **外循环**: 从数组第二个元素（下标为1）开始遍历到末尾，`i` 为当前待插入元素的下标。
2.  **暂存**: 将 `A[i]` 的值存入临时变量 `temp`，防止后续移动时被覆盖。
3.  **内循环 (寻找插入位置并后移)**: 设置指针 `j = i - 1`，从已排序部分的末尾向前扫描。
4.  **比较与后移**: 当 `j >= 0` 且 `A[j] > temp` 时，将 `A[j]` 的值赋给 `A[j+1]`（元素后移），然后 `j--`。
5.  **插入**: 内循环结束后，`j+1` 即为 `temp` 的正确插入位置，执行 `A[j+1] = temp`。

**冒泡排序 (Bubble Sort) - 优化版:**

1.  **外循环**: 控制排序的总轮数。每一轮将一个未排序部分的最大值“冒泡”到其最终位置。范围从 `n-1` 递减到 `1`。
2.  **设置标志位**: 在每轮内循环开始前，设置一个布尔标志 `flag = false`。
3.  **内循环 (相邻比较与交换)**: 从数组第一个元素（下标为0）开始，比较 `A[j]` 和 `A[j+1]`，直到该轮的末尾。
4.  **交换**: 如果 `A[j] > A[j+1]`，则交换两者位置，并将 `flag` 置为 `true`。
5.  **优化判断**: 一轮内循环结束后，如果 `flag` 仍为 `false`，说明本轮未发生任何交换，整个序列已有序，可提前 `break` 结束排序。

### **典型实例与应用技巧 (Examples & Application Techniques):**

**实例**: 对数组 `{5, 2, 3, 5, 1, 6, 4}` 进行直接插入排序。

*   **第一轮 (处理元素2)**: `temp = 2`。`5 > 2`，5后移。2插入到最前面。数组变为 `{2, 5, 3, 5, 1, 6, 4}`。
*   **第二轮 (处理元素3)**: `temp = 3`。`5 > 3`，5后移。`2 < 3`，停止。3插入到2后面。数组变为 `{2, 3, 5, 5, 1, 6, 4}`。
*   ... 后续轮次以此类推。

**技巧**: 冒泡排序的优化标志位是关键，对于近乎有序的序列，它可以极大提高效率，使其时间复杂度接近 $O(n)$。

## 2. 核心主题二: 基于单链表的排序算法

### **目标与定义 (Objective & Definition):**

本模块旨在解决如何在链式存储结构上，仅通过修改节点的指针域，实现链表的原地排序 ($O(1)$ 空间复杂度)。

*   **链表直接插入排序**: 依次将原链表中的节点拆下，并插入到一个新的、始终保持有序的链表中。
*   **链表简单选择排序**: 依次从待排序链表中找出值最大（或最小）的节点，拆下并使用头插法（或尾插法）构建新的有序链表。

### **关键原理与公式 (Core Principles & Formulas):**

*   **原理**: 链表排序的核心在于**节点拆卸**与**重新链接**。所有操作都通过修改 `next` 指针完成，而非移动数据。双指针（前驱 `pre` 和当前 `p`）是实现这些操作的基础。
*   **头插法原理**: 将节点插入到头结点的直接后继位置。如果反复将序列中的最大值头插，最终会形成一个升序链表。
*   **公式**:
    *   时间复杂度: 两种方法的实现均为 $O(n^2)$。
    *   空间复杂度: 均为 $O(1)$ (若不计递归栈空间)。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

**链表直接插入排序 (模块化方法):**

1.  **主函数 (`sortList`)**:
    a. 处理边界情况（空链表或单元素链表）。
    b. 将原链表的第一个节点作为有序链表的初始状态，其余节点作为待排序链表。将第一个节点的 `next` 设为 `NULL`。
    c. 循环遍历待排序链表，每次取下头一个节点 `q`。
    d. 调用辅助函数 `insert(sorted_head, q)` 将节点 `q` 插入到有序链表中。
2.  **辅助函数 (`insert(head, q)`)**:
    a. 使用双指针 `pre` (从头结点开始) 和 `p` (从第一个数据节点开始) 遍历有序链表。
    b. 移动 `pre` 和 `p`，直到找到第一个 `p->data >= q->data` 的位置，或 `p` 到达链表末尾。
    c. 将 `q` 插入到 `pre` 和 `p` 之间 (`q->next = p; pre->next = q;`)。

**链表简单选择排序 (头插法):**

1.  **初始化**: 创建一个新的头结点 `new_head`，这将是最终排好序的链表。原链表头 `head` 之后的序列是待排序区。
2.  **外循环**: 当待排序区不为空时，持续循环。
3.  **内循环 (查找最大值)**:
    a. 遍历整个待排序区，使用 `p_max` 记录值最大节点的指针，`pre_max` 记录其前驱节点的指针。
    b. 遍历完成后，`p_max` 指向当前待排序区的最大值节点。
4.  **拆卸节点**: 通过 `pre_max->next = p_max->next` 将 `p_max` 节点从原链中断开。
5.  **头插**: 调用头插法，将 `p_max` 节点插入到 `new_head` 之后。
6.  **返回**: 外循环结束后，返回 `new_head`。

### **典型实例与应用技巧 (Examples & Application Techniques):**

**实例**: 对链表 `5 -> 2 -> 3 -> ...` 进行选择排序。
1.  **第一轮**: 遍历发现最大节点是 `6`。将其拆下，头插入新链表。新链表为 `6`。原链表变为 `5 -> 2 -> 3 -> 5 -> 1 -> 4`。
2.  **第二轮**: 遍历发现最大节点是第一个 `5`。将其拆下，头插入新链表。新链表为 `5 -> 6`。
3.  ... 以此类推，最终新链表为 `1 -> 2 -> 3 -> 4 -> 5 -> 5 -> 6`。

**技巧**:
*   **空间换时间**: 如果题目不限制空间复杂度，最优策略是将链表数据存入数组，用快速排序 ($O(n \log n)$)，再写回链表。
*   **增加头结点**: 在处理子链表时，为其增加一个临时的头结点可以极大简化对第一个元素的操作，避免复杂的 `if-else` 判断。

## 3. 核心题型一: 验证数据结构特性——判断数组是否为大根堆

### **目标与定义 (Objective & Definition):**

本模块旨在解决如何验证一个给定的数组是否满足大根堆的两个核心属性。

*   **结构属性**: 数组表示的树必须是一棵**完全二叉树**。 (数组存储本身隐含了此属性)
*   **堆序属性**: 所有父节点的值必须**大于或等于**其左右两个子节点的值。

### **关键原理与公式 (Core Principles & Formulas):**

*   **原理**: 检验大根堆的性质，无需递归，只需从上到下遍历所有的**分支节点**（非叶子节点），确保每个分支节点都大于等于其孩子即可。
*   **公式 (数组下标从0开始)**:
    *   节点 `i` 的左孩子: `$2i + 1$`
    *   节点 `i` 的右孩子: `$2i + 2$`
    *   最后一个分支节点的下标: `$\lfloor n/2 \rfloor - 1$`

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

1.  **定位检查范围**: 计算出最后一个分支节点的下标 `last_parent_idx = n/2 - 1`。
2.  **循环遍历**: 使用 `for` 循环，从 `i = 0` 遍历到 `last_parent_idx`。
3.  **检查左孩子**: 计算左孩子下标 `left = 2*i + 1`。如果 `A[i] < A[left]`，则不满足大根堆性质，立即返回 `false`。
4.  **检查右孩子 (注意边界)**: 计算右孩子下标 `right = 2*i + 2`。首先判断 `right` 是否小于数组长度 `n`（即右孩子是否存在）。如果存在且 `A[i] < A[right]`，则不满足大根堆性质，立即返回 `false`。
5.  **返回成功**: 如果循环正常结束，说明所有分支节点都满足条件，返回 `true`。

### **典型实例与应用技巧 (Examples & Application Techniques):**

**实例**: 判断数组 `{66, 33, 48, 10, 8, 30, 21}` 是否为大根堆 (`n=7`)。
1.  最后一个分支节点下标为 `7/2 - 1 = 2`。需检查下标 0, 1, 2。
2.  **i = 0**: `A[0]=66`。左孩子`A[1]=33`，右孩子`A[2]=48`。`66 > 33` 且 `66 > 48`，通过。
3.  **i = 1**: `A[1]=33`。左孩子`A[3]=10`，右孩子`A[4]=8`。`33 > 10` 且 `33 > 8`，通过。
4.  **i = 2**: `A[2]=48`。左孩子`A[5]=30`，右孩子`A[6]=21`。`48 > 30` 且 `48 > 21`，通过。
5.  循环结束，所有分支节点均满足条件，返回 `true`。

**技巧**: 核心技巧在于处理右孩子时的**边界检查** (`right < n`)，这是防止数组访问越界最常见的陷阱。

## **核心原理与解题启发 (Core Principles & Problem-Solving Heuristics)**

### **启发1: 模块化与封装 (Modularity & Encapsulation)**
- 将复杂的算法问题分解为一系列更小、功能单一的子任务，并将其实现为独立的辅助函数（如 `insert`、`swap`、`head_insert`）。这种方法不仅能让主逻辑代码变得异常清晰，还能提高代码的复用性，是处理复杂算法题的通用高级策略。

### **启发2: 双指针法 (Dual-Pointer Technique for Linked Lists)**
- 在对单链表进行任何需要修改链接关系的操作（插入、删除）时，维持一个指向当前节点 `p` 和一个指向其前驱节点 `pre` 的双指针组合，是解决此类问题的“万能钥匙”。它避免了回头查找前驱的低效操作，是链表算法的基本功。

### **启发3: 形象化驱动编码 (Visualization-Driven Coding)**
- 当面对抽象的算法逻辑，特别是涉及复杂指针操作的链表问题时，不要只依赖大脑。在草稿纸上画出数据结构，手动模拟算法的每一步（指针如何移动、节点如何增删），是理清逻辑、发现边界情况、并将思路转化为无误代码的最有效手段。

### **启发4: 空间换时间 (Space-Time Trade-off)**
- 在解题时要对题目的约束条件（尤其是空间复杂度）保持敏感。如果题目没有“原地”或 $O(1)$ 空间的要求，大胆考虑使用额外空间来简化问题或提高时间效率。例如，“链表排序”问题就可以通过转换为“数组排序”来利用更高效的算法，这是一种重要的解题思维。

#  强化课试卷

### **1. 核心定义与前提 (Core Definitions & Premises)**

*   **一元多项式相加**: 本质是将两个按指数升序排列的单链表进行“归并”操作。特殊之处在于，指数相同的项需要合并，即系数相加。
*   **航班排班表合并**: 将N个独立的、按起飞时间有序的单链表，合并成一个总的、全局有序的单链表。
*   **最少换乘次数**: 在一个无向无权图中，从一个顶点（城市）到另一个顶点的**最短路径长度**。路径长度以边的数量计。
*   **平衡因子 (Balance Factor, BF)**: 二叉树中任一节点的左子树高度与右子树高度之差，即 $BF = H_L - H_R$。
*   **并查集 (Disjoint Set / Union-Find)**: 一种用于处理不相交集合的合并与查询问题的数据结构。在此场景下，用于维护和查询“朋友圈”（连通分量）。
*   **前提与假设**:
    *   **试卷难度定位**: 本次模拟试卷的整体难度和代码量均**高于**408统考的平均水平，旨在进行高强度训练。
    *   **算法选择**: 对于无权图的最短路径问题，广度优先搜索（BFS）是标准且高效的解决方案。
    *   **解题策略**: 在考试中，若没有明确的效率要求，优先选择实现简单、不易出错的算法（如顺序查找）；若有，则需采用更优算法（如二分查找）。

### **2. 定理、原理与定律 (Theorems, Principles & Laws)**

*   **有序链表归并原理**: 通过同步遍历两个有序链表，比较当前节点值，将较小者摘下并链接到结果链表的尾部，直至一个链表为空，再将另一个链表的剩余部分全部链接过去。
*   **广度优先搜索 (BFS) 求最短路径原理**: BFS按层次顺序遍历图，从起点开始，逐层向外扩展。由于它首先访问所有距离为k的节点，然后才访问距离为k+1的节点，因此当它第一次到达目标节点时，所经过的路径必然是边数最少的路径（即最短路径）。
*   **后序遍历（左右根）计算节点属性原理**: 一个节点的某些属性（如高度、平衡因子）依赖于其子树的属性。后序遍历保证在处理根节点之前，其左右子树已经完全处理完毕并返回了所需信息（如高度），从而使根节点的计算成为可能。
*   **并查集操作原理**:
    *   **Find**: 通过父指针链向上回溯，直到找到根节点（根节点的父指针通常为负数或指向自身），以确定元素所属的集合。
    *   **Union**: 合并两个集合时，先分别找到两个元素所在集合的根，然后将一个根指向另一个根，从而将两棵树合并为一棵。

### **3. 关键公式与方程 (Key Formulas & Equations)**

*   **二路归并时间复杂度**: 对于长度为 $n$ 和 $m$ 的两个链表，归并操作的时间复杂度为 $O(n+m)$。
*   **BFS时间复杂度**:
    *   基于邻接矩阵: $O(V^2)$ (V为顶点数)
    *   基于邻接表: $O(V+E)$ (E为边数)
*   **二叉树高度递归定义**: $Height(T) = \begin{cases} 0 & \text{if } T \text{ is empty} \\ \max(Height(T_L), Height(T_R)) + 1 & \text{otherwise} \end{cases}$
*   **平衡因子计算**: $BF(node) = Height(node \to left) - Height(node \to right)$
*   **二分查找时间复杂度**: $O(\log_2 n)$

### **4. 逻辑推导与解题过程 (Logical Derivations & Problem-Solving Processes)**

*   **多项式相加 (链表归并变种)**:
    1.  使用双指针 `pa` 和 `pb` 分别遍历链表A和B，并用 `pprea` 记录 `pa` 的前驱。
    2.  循环比较 `pa` 和 `pb` 指向节点的指数，分三种情况处理：
        *   `pa->exp < pb->exp`：A中当前项指数更小，指针 `pa` 和 `pprea` 后移。
        *   `pa->exp == pb->exp`：指数相同。将 `pb` 的系数累加到 `pa` 的系数上，然后释放 `pb` 指向的节点，`pb` 指向B的下一个节点。`pa` 和 `pprea` 后移。
        *   `pa->exp > pb->exp`：B中当前项指数更小。将 `pb` 节点从B中拆下，插入到 `pprea` 和 `pa` 之间。`pb` 指向B的下一个节点。
    3.  循环结束后，若B链表仍有剩余，将其全部链接到A链表的末尾。

*   **求最少换乘次数 (BFS)**:
    1.  初始化：一个队列（可用数组模拟），一个 `visited` 数组标记访问状态，一个 `distance` 数组记录到起点的距离。
    2.  将起点 `start` 入队，标记为已访问，`distance[start] = 0`。
    3.  当队列不为空时，循环执行：
        a. 队头元素 `u` 出队。
        b. 遍历 `u` 的所有邻接点 `v`（通过邻接矩阵）。
        c. 若 `v` 未被访问过：标记 `v` 为已访问，设置 `distance[v] = distance[u] + 1`。
        d. **核心判断**: 如果 `v` 是终点 `end`，则直接返回 `distance[v]`。
        e. 将 `v` 入队。
    4.  若队列为空循环结束仍未找到终点，则说明不可达，返回-1。

*   **计算所有节点的平衡因子 (后序遍历)**:
    1.  设计一个递归函数，其**返回值**为当前子树的高度。
    2.  **递归基**: 如果当前节点为空，返回高度0。
    3.  **递归步骤**:
        a. 递归调用该函数处理左子树，获得左子树高度 `L_H`。
        b. 递归调用该函数处理右子树，获得右子树高度 `R_H`。
        c. **计算与赋值**: 在当前节点，计算平衡因子 `BF = L_H - R_H` 并存入节点的相应字段。
        d. **返回高度**: 向上一层调用返回当前子树的高度 `max(L_H, R_H) + 1`。

### **5. 应用技巧与注意事项 (Application Techniques & Critical Caveats)**

*   **代码模块化**: 将核心、可复用的操作（如两个有序链表的归并`merge`）封装成独立的辅助函数，可以极大简化主逻辑的复杂度和代码量。

*   **模拟数据结构**: 在考试中，对于队列这类辅助结构，可以使用一个简单数组配合头尾指针（`front`, `rear`）进行模拟，代码实现比定义完整的数据结构更快捷。
*   **自创测试用例**: 当题目给出的示例不足以覆盖所有逻辑分支时，应主动设计新的、针对性强的测试用例来辅助自己理清思路。

*   **向上/下传递信息**:
    *   **向上**: 利用递归函数的**返回值**，将子问题的解（如子树高度）传递给父问题。
    *   **向下**: 利用递归函数的**参数**，将父节点的信息（如节点深度）传递给子节点。

## 1. 核心主题一: 有序单链表的归并及其变种

### **目标与定义 (Objective & Definition):**

本模块旨在解决将两个或多个有序单链表合并为一个全局有序单链表的问题，并处理归并过程中的特殊合并规则。

*   **多项式相加**: 将两个按指数升序的链表归并，其中指数相同的节点需要合并（系数相加），而非简单地并列。
*   **多航班表合并**: 将N个有序链表通过类似“二路归并”的迭代操作，最终合并成一个总表。

### **关键原理与公式 (Core Principles & Formulas):**

*   **原理**: 核心是“穿针引线”。利用工作指针在两个（或多个）链表间移动，比较节点大小，并不断将胜出者链接到结果链表的尾部。处理所有指针（前驱、当前、被合并链表）的正确更新是关键。
*   **公式**:
    *   二路归并时间复杂度: $O(n+m)$
    *   N路迭代归并时间复杂度（朴素实现）: $O(\sum_{i=1}^{N} L_i \times N)$，其中 $L_i$ 是各链表长度，效率较低。更优化的方法（如败者树、最小堆）可达 $O(L_{total} \log N)$。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

**通用二路归并框架 (将`h2`并入`h1`):**

1.  **初始化**: 创建工作指针 `p1`, `p2` 分别指向 `h1` 和 `h2` 的首个数据节点，`pre` 指向 `h1` 的头结点。
2.  **主循环**: 当 `p1` 和 `p2` 都不为空时：
    *   **情况1 (`p1`值 &lt;= `p2`值)**: `p1` 已经是正确位置，只需后移 `pre` 和 `p1`。
    *   **情况2 (`p1`值 &gt; `p2`值)**: `p2` 需要插入到 `pre` 和 `p1` 之间。
        a. 从 `h2` 中拆下 `p2` (保存 `p2` 的后继，更新 `h2` 的链头)。
        b. 将 `p2` 插入 `h1` 中 (`pre->next = p2; p2->next = p1;`)。
        c. 更新 `pre` 指向刚插入的 `p2`，`p2` 指向之前保存的后继节点。
3.  **收尾**: 循环结束后，若 `h2` 还有剩余节点 (`p2 != NULL`)，将 `h2` 的剩余部分全部链接到 `h1` 的末尾（即 `pre` 之后）。

**多项式相加的特化处理**: 在上述框架的 `p1->exp == p2->exp` 的情况中，执行系数相加和节点释放操作，而不是插入。

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **实例**: 合并 `h1 = {1->5->9}` 和 `h2 = {2->4->10}`。
    1. `1 < 2`，`p1` 后移。
    2. `5 > 2`，将 `2` 插入到 `1` 和 `5` 之间。`h1` 变为 `{1->2->5->9}`。
    3. `5 > 4`，将 `4` 插入到 `2` 和 `5` 之间。`h1` 变为 `{1->2->4->5->9}`。
    4. `9 < 10`，`p1` 后移。`p1` 为空，循环结束。
    5. `h2` 剩余 `{10}`，链接到 `9` 之后。最终结果 `{1->2->4->5->9->10}`。
*   **技巧**: **强烈推荐封装 `merge` 函数**。对于多项式相加或多链表合并这类复杂问题，先实现一个标准的、健壮的二路归并函数，然后在主逻辑中调用它，可以极大地降低心智负担和出错率。

## 2. 核心主题二: 图的遍历应用——求解无权图最短路径

### **目标与定义 (Objective & Definition):**

本模块旨在应用广度优先搜索（BFS）算法，高效求解无向、无权图中任意两点间的“最少换乘次数”，即最短路径长度。

### **关键原理与公式 (Core Principles & Formulas):**

*   **原理**: BFS的层次遍历特性天然地保证了路径最短。它从起点开始，像水波纹一样逐层扩展，第一次到达目标节点时所经过的层数，即为最短路径长度。
*   **必备辅助结构**:
    1.  **队列**: 存储待访问的节点，保证“先进先出”的层次访问顺序。
    2.  **`visited`数组**: 避免节点重复访问和陷入死循环。
    3.  **`distance`数组**: 记录从起点到每个节点的最短距离。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

1.  **初始化**:
    *   创建一个队列 `Q`（可用数组和头尾指针模拟）。
    *   初始化 `visited` 数组所有值为 `false`。
    *   初始化 `distance` 数组所有值为-1（或无穷大）。
2.  **起点处理**:
    *   将起点 `start` 入队 `Q.enqueue(start)`。
    *   标记起点 `visited[start] = true`。
    *   设置起点距离 `distance[start] = 0`。
3.  **BFS主循环**: 当队列 `Q` 不为空时：
    *   队头元素 `u = Q.dequeue()` 出队。
    *   **核心逻辑**: 遍历 `u` 的所有邻居 `v`：
        *   如果 `v` **未被访问** (`!visited[v]`)：
            *   标记 `visited[v] = true`。
            *   更新距离 `distance[v] = distance[u] + 1`。
            *   **判断终点**: 如果 `v == end`，算法成功，直接 `return distance[v]`。
            *   将 `v` 入队 `Q.enqueue(v)`。
4.  **失败返回**: 若循环结束仍未找到终点，说明两点不连通，`return -1`。

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **实例**: 在讲稿的图中，求1到5的最短路径。
    1. 队列: `{1}`，`dist[1]=0`。
    2. 1出队，邻居0,3,4入队。队列: `{0,3,4}`，`dist[0]=1, dist[3]=1, dist[4]=1`。
    3. 0出队，邻居2入队。队列: `{3,4,2}`，`dist[2]=2`。
    4. 3出队，邻居5入队。队列: `{4,2,5}`，`dist[5]=2`。
    5. **找到终点**: 发现邻居5是终点，直接返回 `dist[5]` 的值，即2。
*   **技巧**: 考试时，用数组和 `front`/`rear` 指针模拟队列是最快的实现方式，可以节省定义结构体和函数的时间。此模板不仅能求最短路径，也能用来判断图的连通性。

## 3. 核心主题三: 并查集及其应用

### **目标与定义 (Objective & Definition):**

本模块旨在应用并查集数据结构，快速判断动态变化的集合中，任意两个元素是否属于同一个集合（在图中即是否连通）。

*   **场景**: "朋友圈"问题，初始时每个人都是一个独立的圈子，当两人成为朋友时，他们所在的两个圈子合并。需要快速查询任意两人是否在同一个圈子内。

### **关键原理与公式 (Core Principles & Formulas):**

*   **原理**: 使用一个数组 `parent[]` 表示一个由多棵树构成的森林。每个集合是一棵树，数组元素 `parent[i]` 存储节点 `i` 的父节点。树的根节点代表整个集合。
*   **核心操作**:
    *   `Find(i)`: 从节点 `i` 开始，沿着 `parent` 指针向上查找，直至找到根节点。
    *   `Union(i, j)`: 先通过 `Find` 找到 `i` 和 `j` 的根 `root_i` 和 `root_j`，然后令 `parent[root_i] = root_j`，实现合并。
*   **路径压缩优化**: 在 `Find` 操作时，将查找路径上的所有节点直接指向根节点，可以极大提高后续查找效率。

### **方法论/解题步骤 (Methodology / Step-by-Step Solution):**

1.  **数据结构定义**: `int parent[N];` 即可。`parent[i]` 为负数表示 `i` 是根，其绝对值为集合大小；为正数表示其父节点的下标。
2.  **初始化**: `for(i=0; i<N; i++) parent[i] = -1;` 使每个元素自成一个集合。
3.  **成为朋友 (`Union(i, j)`)**:
    *   `int root_i = Find(i);`
    *   `int root_j = Find(j);`
    *   如果 `root_i != root_j`，则执行合并 `parent[root_i] = root_j;` (可带按秩合并优化)。
4.  **查询是否在同一朋友圈**: `return Find(i) == Find(j);`

### **典型实例与应用技巧 (Examples & Application Techniques):**

*   **技巧**: 并查集是处理动态连通性问题的首选数据结构，其近乎 $O(1)$ 的均摊时间复杂度远优于图的遍历方法。虽然二二年才加入大纲，但其思想简洁、代码实现简短，非常适合作为算法题的考点，需高度重视。
