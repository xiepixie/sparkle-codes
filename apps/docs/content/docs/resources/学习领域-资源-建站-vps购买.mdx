# VPS 采购与服务部署配置指南

以下为线上生产环境节点的硬件与网络配置标准。

* **节点名称**: Tokyo-Node1 (xpx2483)
* **机房位置**: 日本东京
* **网络特征**: 中国大陆优化线路，流媒体解锁良好，公平共享带宽
* **CPU**: Intel® Xeon® Gold 6230 系列 (4 核)
* **内存**: 4 GB DDR4
* **存储**: 60 GB NVMe 固态硬盘
* **带宽**: 300 Mbps (突发)
* **流量**: 1000 GB (出站)

* **资源策略**: 禁止长期占用突发带宽和 CPU

## 二、 服务器远程管理与 SSH 配置

为确保服务端的运维安全及登录效率，采用 Ed25519 密钥认证，并通过本地 `~/.ssh/config` 进行多权限用户的环境隔离。

### 1. SSH 客户端免密配置

将以下配置写入本地客户端环境，实现普通用户（`xpx`）与超级管理员（`root`）的快捷访问：

```text
Host tokyo-saas
  HostName 154.36.155.185
  User xpx
  Port 22
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
  AddKeysToAgent yes
  UseKeychain yes
  ServerAliveInterval 60
  ServerAliveCountMax 3
  TCPKeepAlive yes
  StrictHostKeyChecking ask
  
Host tokyo-root
  HostName 154.36.155.185
  User root
  Port 22
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
  AddKeysToAgent yes
  UseKeychain yes
  ServerAliveInterval 60
  ServerAliveCountMax 3
  TCPKeepAlive yes
  StrictHostKeyChecking ask
```

### 2. 面板安全访问策略

为收敛公网攻击面，1Panel 运维面板不建议直接暴露公网端口，推荐通过 SSH 本地端口转发建立安全隧道进行管理：

```bash
ssh -L 8888:127.0.0.1:28443 root@154.36.155.185
```

## 四、 SSL/TLS 证书自动化与 Web 服务配置

以部署 `sparkle.codes` 为例，实现从 CDN 到源站的端到端加密。

### 1. 创建 Cloudflare API Token (用于 DNS 验证自动续签)

* 访问 Cloudflare API Tokens 控制台，点击“创建令牌”。
* 选择模板：**编辑区域 DNS (Edit zone DNS)**。
* 配置权限：`Zone` - `DNS` - `Edit`。
* 配置区域资源：`Include` - `Specific zone` - `sparkle.codes`。
* 生成并妥善保管长效 API Token 密钥。

### 2. 1Panel Web 站点配置

* **工作目录**: `/opt/1panel/apps/openresty/openresty/www/sites/sparkle.codes/index`
* 进入 1Panel 网站管理设置，定位至 HTTPS 模块。
* **启用 HTTPS**: 选择通过 API 成功申请的正式证书（替代自签名证书）。
* **启用 HTTP/2**: 勾选开启，大幅降低日本源站至访客浏览器的传输延迟与并发开销。
* **强制 HTTPS**: 勾选开启，统一入口流量。

### 3. Cloudflare 加密策略收紧

源站 1Panel 证书配置完毕后，需执行最终的 CDN 安全策略：

* 进入 Cloudflare 控制台 -> `SSL/TLS` -> `概述 (Overview)`。
* 将加密模式由灵活/完全，提升为 **完全 (严格) / Full (Strict)**。
* 此模式下，Cloudflare 将强制验证源站证书的合法性，彻底杜绝中间人攻击。
